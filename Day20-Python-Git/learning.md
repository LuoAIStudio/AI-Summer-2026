# Day 20：`__new__` / 单例设计模式 / 异常处理

## 今日主题
- `__new__` 方法：为对象**分配内存空间**。
- **单例设计模式**：让一个类无论创建多少次，返回的都是**同一个对象**。
- 异常处理：捕获异常、异常的传递、主动抛出异常。

## `__new__` 方法
- 作用：**为对象分配内存空间**，是"造对象"的第一步；`__init__` 只是给造好的对象"装修"。
- 执行顺序：先 `__new__`，后 `__init__`。
- 必须写成 `instance = super().__new__(cls)` 再用 `return` 返回，否则 Python **不知道对象该引用哪里**。
- `__new__` 本质是**静态方法**，所以第一个参数要手动写 `cls`（表示类本身）。
- 对比记忆：
  - `__new__`：第一个参数 `cls`，此时**对象还没出生**，负责"生"。
  - `__init__`：第一个参数 `self`，此时**对象已经存在**，负责"养"。

## 单例设计模式
- 目标：一个类**只创建一个实例**，每次 `类名()` 拿到的都是**同一块内存上的同一个对象**（`id()` 相同、`is` 为 `True`）。
- 实现三步：
  1. 定义**类属性**当"仓库"：`instance = None`。
  2. 重写 `__new__`：先判断 `if cls.instance is None:`，没造过就 `cls.instance = super().__new__(cls)`。
  3. 最后无论造没造过都 `return cls.instance`。
- 一句话理解：**在分配内存之前先做判断**——仓库是空的就分配并存进去，仓库有货就直接把旧的返回。
- **为什么要让它落在同一个内存位置**：属性（状态）是存在对象自己的内存里的。地址相同 = 大家共用同一份属性，改一处、处处生效，不会出现"两个真相"。次要收益是昂贵资源（读配置、建连接、加载模型）只初始化一次。
- 该不该用单例的判断标准：**同时存在两份，系统会出错吗？** 会才用（配置、连接池、日志器、计数器）；不会就别用（比如 Web 里的"当前用户"做成单例会数据串号）。

## `__init__` 只执行一次的坑
- `__new__` 被拦住了，但 **`__init__` 每次调用 `类名()` 仍然会执行**。
- 后果：如果 `__init__` 里做的是"重新读配置""清空列表"，那每次取单例都会把共享状态重置一遍，**单例就白做了**。
- 解法：加一个类属性当**标志位**（`init_flag = False`），`__init__` 里先判断：
  - 标志位还是 `False` → 执行初始化，然后**立刻把它改成 `True`**；
  - 已经是 `True` → 直接 `return`，不再初始化。
- 小提示：判断空值更推荐写 `is None`，而不是 `== None`。

## 异常基础
- 异常：Python 解释器运行到**不能解释的语法/无法完成的操作**时会停止运行并报错，这个过程叫**抛出异常**。
- 完整结构：
  - `try`：放**不确定能否正常执行**的代码；
  - `except`：出错时的处理（可以写多个，分别对应不同异常）；
  - `else`：**没出错**时才执行；
  - `finally`：**无论是否出错**都执行，用来收尾。
- `except Exception as result`：用一个变量接住异常对象，打印出来，用来兜住"没想到的未知错误"。
- 捕获顺序：**具体的异常写在前面，`Exception` 兜底写在最后**（因为 `Exception` 什么都能抓）。
- `else` 与 `finally` 的区别：`else` 只在**没出错**时执行；`finally` **一定**执行。
- `finally` 真正的价值：当 `try` 里有 `return` / `break` / `continue`，或异常没人捕获继续往上抛时，**它后面的代码不会执行，但 `finally` 依然会执行** → 适合释放资源（关文件、关连接）、恢复现场。注意：`finally` 里不要写 `return`（会吞掉异常或覆盖返回值）。

## 异常的传递
- 异常会沿着**函数调用链一层层往上抛**，直到有人处理它为止。
- 所以在多层函数调用里，**函数内部不用层层写 try/except**，只要在**主程序（最外层调用处）**处理一次就够了。
- 如果一路传到主程序还是没人处理 → 程序终止运行。

## 主动抛出异常
- 场景：用户输入不符合要求时，与其悄悄返回一个奇怪的值，不如**主动"报错"**告诉调用方。
- 写法：先创建异常对象并用字符串描述原因，再 `raise` 抛出去：
  - `ex = Exception("请输入5位及以上长度的密码")`
  - `raise ex`
- 上层用 `try/except Exception as result` 捕获后打印 `result`，这段描述信息就能展示给用户。

## 容易踩的坑
1. **`except Exception` 必须放在最后**：`Day20.py` 里把 `except Exception as result` 写在了 `except(ZeroDivisionError)` **前面**，于是除零错误会被 `Exception` 先抓走，后面那个 `except(ZeroDivisionError)` 成了**永远执行不到的死代码**（注释里已经写了"一般放在最后"，但位置放反了，调换过来即可）。
2. **单例的 `__init__` 会重复执行** → 必须用标志位挡住，否则状态每次被重置。
3. **`__new__` 忘了 `return`**：不返回就没有对象，`__init__` 也不会被调用。
4. **类属性和类方法同名会互相覆盖**：`项目.py` 里类属性 `show_top_score = 0` 和类方法 `show_top_score()` **重名**，类方法把类属性覆盖掉了；于是类方法里 `cls.show_top_score` 拿到的是**方法本身**，`"%d" % 方法` 会报类型错误。建议改名区分（比如类属性叫 `top_score`，类方法叫 `show_top_score_info()`）。
5. **`__new__` 的参数**：目前 `def __new__(cls)` 只能支持无参创建；以后若要用 `Player("小明")` 这种带参形式，需要写成 `def __new__(cls, *args, **kwargs)`，否则会报参数错误。
6. 小拼写：代码里的 `dome` 应为 `demo`（演示）。
